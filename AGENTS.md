# Squidwool contributor guide

## Project
Squidwool is a fast, static utility site for SQU students. It has no runtime backend: the frontend searches a versioned, compressed course/timetable dataset generated by Python and published with the site.

Initial tools:
1. **Schedule Builder** — course selections in, valid timetable combinations out.
2. **Empty Room Finder** — day/time/building filters in, rooms with no scheduled class out.

The current milestone is **data gathering and normalization**, not the frontend.

## Planned stack
- Solid 2 + TypeScript, Vite, plain CSS
- Python for acquisition, validation, normalization, and compression
- Compressed JSON as app data
- localStorage / IndexedDB only for client preferences and cached data
- GitHub Pages hosting; GitHub Actions for scheduled/manual data refreshes

## Repository layout
- `docs/` — product, data-contract, and operational decisions
- `scripts/` — Python pipeline code (future)
- `data/raw/` — unmodified source captures; do not edit by hand
- `data/processed/` — generated artifacts; do not edit by hand
- `.github/workflows/` — refresh and deployment automation (future)

## Data rules
- Treat source captures as evidence: record source URL, retrieval timestamp, academic term, and checksum.
- Keep raw and generated data separate. Transformations must be reproducible from raw inputs.
- Validate before publishing: required fields, stable identifiers, day/time parsing, room/building extraction, duplicates, and conflicts.
- Never commit credentials, session cookies, or private student data. Use GitHub Actions secrets only when a source requires authentication.
- Prefer official, publicly accessible SQU sources. Document any inferred or incomplete field.
- Preserve unknown values explicitly (`null`/`unknown`); do not invent room, instructor, or meeting-time data.

## Engineering rules
- Keep the site static and backend-free unless an approved requirement changes this.
- Add a new tool as an isolated feature module that consumes the shared normalized data contract.
- Do not add dependencies or UI implementation while the data contract is unsettled.
- Generated files must state their generator, input version, and generation time.
- Before changing the data shape, update `docs/data-contract.md` and describe compatibility impact.

## Commands
No application or pipeline commands exist yet. Add documented, reproducible commands alongside their implementation.
